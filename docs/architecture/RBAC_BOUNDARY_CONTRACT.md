# 权限边界契约（真源）

> **版本**：1.5（2026-08-24）  
> **地位**：组织 / 项目 / 平台角色的**唯一边界真源**。实现、测试、UI 人设、能力矩阵均对齐本文。  
> **冲突时**：改旧文对齐本文，禁止再开第三份「计划」各说各话。  
> **能力 ID 与 UI 控件映射**：IDE `docs/rbac-capability-matrix.md`（本文管「谁能看见什么」，矩阵管「按钮/API 叫什么」）。

---

## 0. 三句话（先记这个）

1. **组织是租户硬隔离。** A 组织的人看不见 B 组织的项目、设计、制品、任务。  
2. **只有平台管理员能看全部组织。** 组织负责人/管理员再高，也只限于**自己管理的组织**。  
3. **本组织 owner/admin 对本组织下每一个项目都是管理者。** 他们不会、也不允许在本组织项目里被标成 `viewer`。`viewer` 只属于**同一组织内**被单独授权只读的普通人。

不要再使用「组织管理员也可能是项目 viewer，所以要覆盖」这种说法。那种组合在本组织内是非法状态，不是产品语义。

---

## 1. 三层模型

```
平台实例
├── 平台角色（登录身份，不是租户）
│     admin     → 旁路一切组织/项目；运维（预算、Token、purge）
│     operator  → 无平台旁路；实际权限只来自「加入了哪些组织 + 哪些项目」
│
├── 组织 Organization（租户边界）
│     owner / admin  → 管本组织的人、审计、设备池；本组织全部项目 ≡ 项目 owner；默认可建项目、邀请成员  
│     member         → 进了组织 ≠ 进项目；只能看见自己被加入的本组织项目；默认不能建项目、不能邀请  
│                   → 组织策略可打开 `members_can_create_projects` / `members_can_invite`（后者只能邀 member）
│
└── 项目 Project（组织内的工作空间，必须有 org_id）
      owner   → 管成员 + 读写内容
      member  → 读写内容
      viewer  → 只读内容
      成员必须是该项目所属组织的组织成员。禁止把外组织的人直接加进项目。
```

设备 / Runner 池是**组织内软隔离**（调度资格），不是第二条租户边界。不能靠设备列表把外组织数据透出来。

## 2. 谁能看见什么

| 身份 | 看见哪些组织 | 看见哪些项目 | 项目内写 | 管项目成员 | 运维（预算/Token/purge） |
|------|--------------|--------------|----------|------------|--------------------------|
| 平台 `admin` | 全部 | 全部 | 是 | 是 | 是 |
| 组织 `owner` / `admin` | 仅自己加入且任职 owner/admin 的组织 | **该组织下全部项目** | 是 | 是 | 否 |
| 组织 `member` + 项目 `owner`/`member` | 仅自己加入的组织 | 仅被加入的本组织项目 | 是 | 仅项目 owner | 否 |
| 组织 `member` + 项目 `viewer` | 仅自己加入的组织 | 仅被加入的本组织项目 | 否 | 否 | 否 |
| 组织 `member`、未加入任何项目 | 能看见组织本身 | **无** | — | — | 否 |
| 未加入该组织 | 看不见该组织 | 看不见该组织任何项目 | — | — | 否 |
| Runner Token | — | 仅 scope 内已分配任务 | 仅执行面 | 否 | 否 |

同一人可以加入多个组织。每个组织单独结算。加入组织 A 不会打开组织 B。

### 2.1 组织权限开关

组织负责人/管理员（及平台管理员）可在组织设置中调整 `Organization.policies`：

| 开关 | 默认 | 打开后 |
|------|------|--------|
| `members_can_create_projects` | 关 | 本组织 `member` 可创建归属该组织的项目（创建者成为项目 owner） |
| `members_can_invite` | 关 | 本组织 `member` 可邀请已有平台用户加入本组织，**目标角色只能是 member** |

创建组织仍仅平台管理员。开关不能把 member 提升为组织 admin/owner，也不能绕过「进组织 ≠ 进项目」。

## 3. 非法组合（必须拒绝，而不是「覆盖」）

| 状态 | 处理 |
|------|------|
| 本组织 owner/admin 被写成项目 `viewer` / `member` | **禁止写入**；若历史脏数据，求值时仍按项目 owner，列表 `my_role` 下发 `owner` |
| 把**非本组织成员**加成项目成员 | **拒绝**（403/400）。要进项目，先成为该组织成员（组织管理员加人或走邀请入组织） |
| 项目邀请被外组织账号接受 | 接受时**先加入该组织（org member）再入项**；不能只挂 project_members 而人还在隔壁组织 |
| 共享 ACL 授权给外组织用户 | **拒绝**。ACL 只在**同一组织内**做跨项目执行资源分享；设计域不走 ACL |
| 项目没有 `org_id` | **拒绝创建**。项目必须属于某个组织，不是可选字段。库里若仍有脏行，非平台管理员不可见，不得当作兼容口继续写入。 |
| 制品 / 任务 / 计划没有 `project_id` | **拒绝创建**。执行资源必须落在项目里；创建者 + ACL 不是无项目通道。脏行同样只对平台管理员可见，不能再分享。 |

---

## 4. 求值顺序（实现必须按此）

1. 平台 `admin` → 允许（除明确禁止的自毁规则）。  
2. Runner Token → 只走执行面 + scope。  
3. 目标项目必须有 `org_id`，且调用者必须是该组织成员，否则 **deny**（无组织项目、脏的跨组织 `project_members` / ACL 均无效）。  
4. 该组织的 owner/admin → 视同该项目 `project:owner`。  
5. `project_members` 角色 → 读/写/管人。  
6. 执行资源可再查同组织 ResourceAcl。  
7. 默认 deny。

前端 `useCapabilities` 只做体验门禁，**以后端 `rbac.can` 为准**。组织管理员的 `my_role` 对本组织项目固定为 `owner`，页面上不应出现「当前为只读成员」。

## 5. 角色一句话

| 角色 | 一句话 |
|------|--------|
| 平台管理员 | 看全场、做运维。 |
| 组织负责人/管理员 | 管自己的组织；组织里的项目不用再被加一遍，更不能被降成只读。 |
| 组织普通成员 | 进组织只是入场券；项目还要单独加。 |
| 项目负责人 | 管这个项目的人。 |
| 项目成员 | 能改这个项目的内容。 |
| 项目只读 | 只能看这个项目；且必须是本组织的人。 |

组织管理员 **不是** 平台管理员：没有全局 AI 预算、不能发 Runner Token、不能 purge。

## 5.1 ScopePolicy（五维度，禁止一刀切绑项目）

项目是**业务数据归属**，不是全局准入开关。每个动作只取所需维度：

| 维度 | 管什么 | 典型门禁 |
|------|--------|----------|
| **Identity** | 登录身份、平台角色、个人能力 | `requireAuth` |
| **Org** | 租户硬隔离 | `requireOrg` |
| **Project** | 设计/执行业务资产归属 | `requireProjectWrite` / `requireProjectRead` |
| **Billing** | AI 配额；可与数据归属分离 | 合成桶 `__ephemeral__` / `__authoring__` / `__platform__` |
| **Resource** | 设备 / Runner：org + owner + pool + ACL | `requireResourceLease`；**不**把 Device 表硬绑唯一 `project_id` |

| 动作 | Identity | Org | Project | Billing | Resource |
|------|:--------:|:---:|:-------:|:-------:|:--------:|
| 登录 / 组织治理 / Dashboard 概览 | ✓ | 视目标 | — | — | — |
| 设计域读写、制品上传、建 Job/计划 | ✓ | ✓ | **必须** | — | — |
| Web AI 闲聊、IDE `ops/ai/codegen` | ✓ | 可选 | **不必** | 合成桶 | — |
| 设计域 RAG / 生成用例落库 / 审核 | ✓ | ✓ | **必须** | 项目桶 | — |
| 注册 TR 设备（勾选 UDID） | ✓ | 有则跟 Runner | — | — | allowlist |
| 预配远程节点 | ✓ | **必须** | — | — | scoped Token |
| 设备看板、预占、远控 | ✓ | 有组织则隔离 | — | — | 池/ACL/占用 |
| 批跑选设备（调度资格） | ✓ | ✓ | 作**筛选** | — | 池规则 ∩ 项目 |
| IDE 本机 Runner 心跳进 TR 池 | ✓ | 有则写入 Runner | 可选多项目 scope | — | Runner Token |
| IDE 本地 USB / 镜像 / 本地执行 | — | — | — | — | `requireLocalWorkspace` |

**禁止**：用顶栏 `filterProjectId` 过滤公共设备看板；用顶栏组织当作注册 API 必填项；用「未选项目」禁用登录、闲聊、本机 Runner 启动或本机设备注册；把 `canEditProject` 当成通用 AI 开关。  
**仍禁止**：无 `project_id` 的制品 / Job / 计划作为产品入口；给 `Device` 表加唯一 `project_id` 租户列。

## 5.2 公共设备资源（注册 ≠ 使用）

公共实验室设备是**可租用的共享资源**，不是某个项目的私产。组织和项目不要做成同一强度的强绑定。

| 环节 | 跟谁 | 不跟谁 |
|------|------|--------|
| **注册**（扫描勾选 UDID） | 设备挂 Runner；组织软绑在 `Runner.org_id` | **项目**。禁止 `Device.project_id` |
| **预配远程节点** | 必须选组织（这是在建节点，不是在注册 UDID） | 项目。`project_ids` 可空 |
| **无组织体系** | 本机注册 / 已在跑的节点不拦截 | 不得诱导普通成员去「新建组织」 |
| **看板 / 预占 / 远控** | 登录 + 组织可见性 + 占用/ACL | 顶栏项目 |
| **使用**（Job / 计划） | 作业必须有 `project_id`；项目经资源池获得调度资格 | 不改设备归属 |

调度资格（有项目时）取交集：`资源池授权 ∩ Runner.org/scope ∩ 所有权/来源 ∩ 空闲/预占`。组织未建池且项目无授权时走存量兼容（该组织已注册设备可用），不是漏做。

顶栏组织是**过滤器**，不是注册接口必填字段。`PATCH /runners/{id}/device-selection` 只收 `{ action, udids }`。已有 `runner.org_id` 时沿用，不得用顶栏覆盖。
